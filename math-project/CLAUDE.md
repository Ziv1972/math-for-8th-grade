# CLAUDE.md — פרויקט תרגול מתמטיקה כיתה ח'

> מסמך זה הוא נקודת הכניסה של Claude Code לפרויקט. הוא מסכם את כל ההיסטוריה, הארכיטקטורה, ההחלטות והמשימות הפתוחות. קרא אותו במלואו לפני שינוי קוד.
> כל הממשק והתוכן בעברית (RTL). הקוד והמסמך הטכני באנגלית/עברית מעורבב לפי הצורך.

## 1. מטרת הפרויקט

בניית כלי תרגול אינטראקטיביים במתמטיקה לתלמיד/ת **כיתה ח'** בישראל, לקראת **מבחן מועד ב'**. הכלים: משחק תרגול (gamified) ומבחנים אינטראקטיביים עם בדיקה אוטומטית, מעקב ביצועים, ודוח מבוסס AI.

- **קהל**: תלמיד/ה בגיל ~13-14, דובר/ת עברית.
- **ספר הלימוד**: "שבצת" (mishbetzet.co.il). רמת התרגילים מבוססת על צילומי דפים מהספר (כולל נספחי "רמה א/ב" ו"שאלות העמקה").
- **דגש מתמשך**: התלמיד/ה מתקשה ב**מערכות משוואות** — כל מבחן חדש כולל 4/8 שאלות בנושא זה.

## 4. ארכיטקטורה טכנית — תבנית המבחן

כל המבחנים חולקים מבנה זהה. **הבן את התבנית הזו לפני עריכה.**

### 4.1 מבנה הנתונים — `EXAM` array
כל שאלה היא אובייקט:
```javascript
{
  id: "q3",                    // מזהה ייחודי
  topic: "systems",            // אחד מ-8 ה-topics
  points: 14,                  // נקודות (סך כל המבחן = 100)
  title: "מערכת משוואות",
  stem: "...",                 // טקסט השאלה (HTML מותר)
  svg: "<svg>...</svg>",       // אופציונלי — שרטוט
  parts: [                     // תת-סעיפים
    {
      id: "a1",
      label: "(א) x:",
      text: "...",
      type: "number",          // "number" | "mcq"
      answer: 3,               // number: ערך יחיד או מערך [v1,v2]
      tolerance: 0.05,         // אופציונלי
      points: 4,
      hint: "...",             // רמז (תמיד זמין)
      solution: "..."          // פתרון מלא (נעול עד ניסיון — ראה 4.4)
    },
    {
      id: "a2",
      type: "mcq",
      options: ["...","...","..."],
      correct: 1,              // אינדקס התשובה הנכונה
      points: 3,
      solution: "..."
    }
  ]
}
```

### 4.2 מנוע הבדיקה
- `parseNum(s)` — ממיר קלט: תומך בשברים (`3/4`), עשרוני, פסיק/נקודה.
- `approxEq(a,b,tol)` — השוואה עם סבילות. ברירת מחדל: 0.01 למספרים <1, אחרת 0.05.
- `build()` → `makePart(q,p)` — בונה את ה-DOM דינמית מתוך `EXAM`.
- `updateScore()` — סוכם נקודות, מעדכן פס ציון, ומפעיל `showFinish()` כשכל התת-סעיפים נענו.

### 4.2.1 מעקב מתמשך רב-משתמשים — `progress.js` + `index.html` (חדש)
- **חיווט:** כל מבחן (א'–ה') טוען `<script src="progress.js"></script>`, ובראש `showFinish` קורא `if(window.MQ)MQ.record("examN","כותרת",EXAM,earned);`. החיבור גנרי כי כל המבחנים חולקים `EXAM` (עם `topic` לשאלה), מפת `earned` (מפתח `q.id+p.id`), ו-`showFinish`. **אין צורך לערוך את המבחנים** לתכונות חדשות — משך נמדד מזמן טעינת `progress.js`, והרמה נשלפת מ-`CATALOG` לפי `examId`.
- **משתמשים:** נתונים נשמרים פר-שם תחת `mq_progress_v1::<שם>`. `MQ.setUser/listUsers/deleteUser/currentUser`; המשתמש הפעיל ב-`mq_current_user`. הגירה חד-פעמית של נתוני גרסה ישנה (גלובליים) לפרופיל "ברירת מחדל". ללא משתמש פעיל → "אורח".
- **`MQ.record`**: מחשב ציון + פירוט לפי נושא, ומוסיף ניסיון: `{examId,title,ts,score,total,pct,byTopic,durationMs,level,user}`. דה-דופ: `_recorded` לכל טעינת דף.
- **`MQ.aggregate()`** → לכל נושא `last/best/avg/attempts`. **`MQ.recommend()`** → הנושא החלש ביותר + ניתוב למשאב ב`CATALOG` ברמה מתאימה (band לפי הציון האחרון: <60 קל · 60-84 בינוני · ≥85 קשה). **הרמה (`level`) פנימית בלבד — לא מוצגת לתלמיד.**
- **`CATALOG`**: רשימת המבחנים עם `topics` ו-`level` (1/2/3). כיום קיימים רק level 2–3 (מבחנים מסכמים); **חסר תוכן level-1 וממוקד-נושא** (משימה 2 במפה).
- **`index.html`** (הבית): סרגל פרופיל (בחירה/יצירה/החלפה/מחיקה), דוח פר-משתמש (סטטיסטיקה, פסי שליטה, חוזקות/חולשות, ניסיונות אחרונים), והמלצת "הצעד הבא" מ-`recommend()`. **כתוב ב-DOM בטוח** (helper `h()` עם `textContent`/`createElement`, ללא `innerHTML`) — לעמידה במדיניות ה-XSS.
- **מגבלה:** הנתונים פר-דפדפן ופר-origin. `file://` ו-`http://` אינם חולקים localStorage. אין סנכרון חוצה-מכשירים (לפי החלטה: בלי שרת).

### 4.3 RTL + נוסחאות (קל לטעות — שים לב!)
- כל הדף `dir="rtl"`. נוסחאות מתמטיות **חייבות** `dir="ltr"`:
  ```html
  <span class="formula" dir="ltr">y = 2x − 4</span>
  ```
- ה-CSS: `.formula{direction:ltr;unicode-bidi:isolate;...}`
- **באג שתוקן**: הציון `96 / 100` הוצג הפוך כ-`100 / 96` כי ישב ב-RTL. הפתרון: כל מספר ציון/טיימר עטוף ב-`direction:ltr` (ראה `.pct`, `.timer`, `.final-score`, `input.ans`).
- סימנים: מינוס `−` (U+2212, לא hyphen), כפל `·`, חזקה `x²` או `<sup>`, שורש `√`. שברים מורכבים: `<span class="frac"><span class="num">..</span><span class="den">..</span></span>`.
- פירוט מלא: `skill/references/math-notation.md`.

### 4.4 מנגנונים שנוספו הדרגתית
- **exam3/exam4**: פתרון **נעול** (`<button disabled>`) עד שנעשה ניסיון מענה (`unlockSol()`). פתיחת פתרון מסומנת כ"הצצה". בסוף — סיכום נושאים שהוצץ בהם.
- **exam5 (המנוע המתקדם)**: לכל תת-סעיף נשמר ב-`log[key]`:
  ```
  {attempts, wrong, hintUsed, peeked, solved, timeMs, firstTryCorrect, topic, points, ...}
  ```
  - **זמן per שאלה**: `focusPart(key)` בכניסה לקלט, `flushTime()` ביציאה. (מגבלה: סופר זמן idle אם הטאב נשאר פתוח.)
  - **טעויות**: נספרות גם ב-number וגם ב-mcq (mcq ננעל אחרי בחירה אחת — לכן טעות שם = 0 נק').
  - **דוח מקומי**: `aggregateByQuestion()`, `aggregateByTopic()` → טבלה per שאלה, גרף שליטה per נושא, רשימת "נקודות לחיזוק" (טעויות/הצצות/זמן חריג >1.8× ממוצע).
  - **ייצוא AI**: `buildDataPacket()` (JSON), `buildPrompt()` (פרומפט מוכן בעברית). כפתור "העתק נתונים" → הדבקה ב-Claude.
  - **AI היברידי**: כפתור "ניתוח אוטומטי" עושה `fetch` ל-`api.anthropic.com/v1/messages` (model `claude-sonnet-4-20250514`). **עובד רק כ-artifact ב-claude.ai**; מקומית נכשל ב-CORS ונופל ל-fallback של ייצוא.

### 4.5 עיצוב

## 5. נוהג קריטי — אימות מתמטי (חובה!)

**כל תשובה במבחן אומתה ב-Python לפני הבנייה.** זה לא אופציונלי — מבחן עם תשובה שגויה פוגע בתלמיד.

לפני הוספת/שינוי תרגיל, הרץ אימות. דוגמה לדפוס שעבד:
```python
from fractions import Fraction as F
def solve2(a1,b1,c1,a2,b2,c2):
    det = a1*b2 - a2*b1
    return F(c1*b2-c2*b1, det), F(a1*c2-a2*c1, det)
# ודא תוצאות שלמות/הגיוניות. דחה שברים מכוערים או ערכים לא-פיזיים (מחיר שלילי וכו').
```
בפועל, האימות תפס מספר תרגילים שגויים (תוצאות לא-שלמות, מחיר שלילי בבעיה מילולית) — ותוקנו לפני ההרכבה.

**בדיקת תקינות JS לפני סיום** (Node זמין בסביבה):
```bash
# חלץ את ה-<script> ל-/tmp/check.js ואז:
node --check /tmp/check.js
# + בדוק איזון סוגריים: count('{')-count('}') == 0 וכו'
# + ודא סכום נקודות == 100
```

## 6. בעיות ידועות ומגבלות

1. **הוכחות גיאומטריות** — אי אפשר לבדוק טקסט חופשי אוטומטית. הפתרון: פירוק ל-MCQ ("איזה משפט חפיפה?") + דוגמת הוכחה מלאה בטבלת טענה-נימוק.
2. **AI report מקומי** — `fetch` ל-API ייכשל ב-CORS בקובץ מקומי. ה-fallback (ייצוא + הדבקה ב-Claude) הוא המסלול הריאלי עבור המשתמש (שמריץ מקומית).
3. **טיימר per שאלה** — סופר זמן idle אם הטאב פתוח. הזמנים *יחסיים*, לא מדויקים.
4. **דגל "זמן חריג"** — היוריסטיקה (1.8× ממוצע). גס במבחן קצר. אות, לא אבחנה.
5. **localStorage ב-game.html** — עובד מקומית; אם יתארח באתר ייתכן שצריך בדיקה.
6. **מאגר רזרבה ב-game.html** — מוגבל ל-6 שאלות לנושא (כשנגמר, הפתרון נפתח חופשי).
7. **רישוי (`license.js`):** מצב `local` = מרתיע בלבד (ניתן לעקיפה, לא מונע שיתוף). מצב `online` (Apps Script + Sheet) **כן מונע שיתוף** — קוד נקשר למכשיר ראשון, מכשיר אחר נדחה; תומך בביטול/תפוגה/יומן. מגבלות online: דורש אינטרנט בהפעלה; מזהה מכשיר = UUID ב-localStorage (מחיקתו דורשת איפוס תא `device` בגיליון); CORS — Apps Script מ-`script.google.com` עובד עם GET פשוט (כפי שמומש).
